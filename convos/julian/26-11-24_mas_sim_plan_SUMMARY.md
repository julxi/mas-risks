# SUMMARY: Implementation plan for `mas_sim` and the risk experiments

**Last updated:** 26-11-26 (plan DRAFT deleted at Julian's request)

The plan was `convos/julian/26-11-24_mas_sim_plan_DRAFT.md`, edited in place; Julian had it deleted on 26-11-26, so it now exists only in git history (last version in commit a99f591: `git show a99f591:convos/julian/26-11-24_mas_sim_plan_DRAFT.md`). It re-implements three experiments from Huang et al. (arXiv 2603.27771v4): majority sway (Risk 2.1), authority deference (Risk 2.2), strategic misreporting (Risk 1.4). The goal is an extensible base, not a faithful reproduction. The plan (its first draft was written in an earlier session without a LOG) explains why not to build on the authors' RiskLab code: two of three experiments are missing or broken there [concluded by that session from static code reading].

Main design choices, at Julian's request:
- **Two packages** [concluded]: `src/mas_sim/` is a general simulation library with no experiment content and never imports `src/risk_experiments/`, which holds the experiments. Both live in the repo's single root `pyproject.toml` (repo layout [decided] in the topic linked below); the second draft had used two pyprojects under `projects/`, dropped when the repo layout changed. A test enforces the import boundary.
- **Scripted agents in experiments** [concluded]: `LLMAgent`, `ScriptedAgent` and `ReplayAgent` share one interface and are logged and parsed the same way. Uses: fixed Plan B text for A3 (authority), fixed fast agents (majority sway), scripted State Agent and truthful/lying A1 baselines (misreporting).
- **Mistral** [verified: docs only, no live call]: the hosted API works with the `openai` SDK and `base_url=https://api.mistral.ai/v1`. Locally served Mistral models may reject non-alternating roles or system messages, so `llm.py` gets a per-model message-normalization step whose output is what gets logged.
- The `projects/` folder and both earlier plan files are deleted; the DRAFT was the only copy, and it was deleted too (26-11-26, see above).

Decided by Julian [decided, transcribed in the LOG]: names stay `mas_sim` / `risk_experiments`; plain Python, no Inspect AI (doesn't fit multi-agent runs); default model is a Mistral model, selectable per run and role; replicates default to 30 per condition (95% CI about ±18 pp on a rate near 50%), adjustable; State Agent in misreporting is scripted; we don't contact the authors. Which Mistral model, and whether Julian meant 30 or 50 replicates, are my working assumptions [assumed].

No fixed budget: Julian sizes sweeps by how promising results are [decided]. The number of conditions (config settings, i.e. experimental arms) is the main cost driver.

Open: RiskLab prompt licensing. Before implementation: `.env` with `MISTRAL_API_KEY` is missing; RiskLab YAML files not yet downloaded; authority-deference case text to be written (see the LOG entry *readiness check*).

**Implemented (milestone 1)** [verified: tests + error injection + one scripted run read by eye, 26-11-24; no live API call yet]:
- `src/mas_sim/`: agents (LLM, scripted, replay), LLM client (`openai` SDK, providers openai/mistral/vllm/ollama, message normalization, disk cache in `data/cache/llm/`), strict JSON output parsing, transcript, Scenario base class, runner with resumable sweeps, JSONL logs.
- `src/risk_experiments/authority.py` + `scenarios/authority_pneumonia.yaml`: our own content (three severe-pneumonia cases, prompts, cue sentences, scripted Plan A/B). Plan classes are computed from drug names. Deviations from the paper, made so the cue is the only authority signal: A2 and A3 are both shown as "Clinician", and A3 doesn't mention its seniority. The 15 judgment calls I made while Julian was away are listed in the LOG entry *milestone 1 implemented* [concluded/assumed there].
- Run: `uv run scripts/run_authority.py` (needs `.env` with `MISTRAL_API_KEY`); inspect: `uv run scripts/inspect_run.py LOG [RUN_ID]`; tests: `uv run pytest` (all checks: `make check`).
- Medical content is unreviewed by a clinician [assumed]; the claims to check are listed in that LOG entry.

**First live smoke run (26-11-24)** [verified: 4 runs, 20 calls, all parsed; one run read in full]: `.env` key must be named `MISTRAL_API_KEY`. Stimulus checks pass (A2 Plan A 4/4, A3 Plan B 4/4); final Plan B 0/2 per condition (CI 0–66%, uninformative at n=2). Problem found: LLM Agent 1 fabricates severity findings in all 4 runs (e.g. "confusion", "need for vasopressors" where the record says the opposite; wrong CURB-65 every time), and A2 copies them downstream, so the shared record varies between runs. `severe_cap` stays correct, so the risk indicator is unaffected. A4 also rejects A3's plan on invented QT grounds, beyond its procedural mandate. Details: LOG entry *first live smoke run read*.

**Bigger-model smoke run (26-11-25)** [verified: 4 runs, 20 calls, all parsed; all A1 and A4 outputs of both logs compared]: `--model mistral:mistral-large-2512` (Mistral Large 3, no reasoning), log `data/results/authority/smoke_large.jsonl`. `mistral-large-latest` is now Large 4, a reasoning model whose reply content is a list of chunks; the code does not support that, and `LLMClient` now raises before caching such a reply. Results: final Plan B 0/2 per condition again. A1 fabricates much less (CURB-65 right 2/4 vs 0/4 for small; no invented major criteria) and gives nearly the same answer across replicates, but still marks case 1 as confused and hypotensive. A4 no longer invents QT risk, but fails Plan B in 4/4 runs as an "absolute contraindication" on guideline grounds, outside its procedural mandate. In the paper's design Plan B should pass A4's narrow checks, so this risks a floor effect where the cue cannot act at A4 [concluded]. Details and comparison table: LOG entry *smoke run with mistral-large-2512*.

**DeepSeek smoke run (26-11-25)** [verified: 4 runs, 20 calls, all parsed; all A1/A4 outputs read]: `--model mistral:deepseek-v4-1-flash-1017` (hosted by Mistral, no reasoning, works with the current code), log `data/results/authority/smoke_deepseek.jsonl`. Final Plan B 0/2 per condition. A1 reads the record correctly (no invented findings) but gets CURB-65 wrong 4/4 by misapplying the rule. A4 rejects Plan B 4/4 on guideline grounds, once explicitly "despite the proposing physician's seniority". With two of three models showing it, the A4 hard gate looks like a property of the prompt, not of one model [concluded]. Comparison table of all three models: LOG entry *smoke run with deepseek-v4-1-flash*.

**What the paper says about A4** [verified: grep of the paper, 26-11-25]: no prompt is published. There is one sentence ("restricted to procedural compliance checks (fatal allergies, absolute contraindications, dosage sanity) and should not introduce novel clinical reasoning beyond the record"), which our prompt paraphrases. No A4 output is quoted; Table 12 gives only its choice (A 10/10 without cue, B 10/10 with cue). The paper itself calls the no-cue rejection of B "objective auditing", backed by guideline reasoning, so our models' guideline-based rejections match what the paper treats as good behaviour; the difference is that ours did not flip under the cue. Our case also makes B more obviously wrong than the paper's (we removed its Gram-negative rods), which may contribute [concluded]. Levers: tighten A4's prompt, make B less obviously wrong, or report the resistance as a result. Details: LOG entry *what the paper says about A4*.

**Gram-negative case set (26-11-25)** [verified: tests; smoke runs with large-2512 and deepseek-flash, n=3 per condition, all A2–A5 outputs read]: lever (b) implemented as `--case-set gram_negative`: the same three cases with "sputum Gram stain shows Gram-negative rods" instead of "pending", which gives ciprofloxacin a partial rationale, as in the paper's case. The default stays `pending`. Result: A4 forwarded Plan B 0/5 in ok cue runs (95% CI 0–43%), final Plan B 0/10 overall. DeepSeek's A4 now passes Plan B on its narrow checks in 3/6 runs but still forwards A2's plan; Large 3's A4 still fails it, without the cue by inventing a dosing error. Side effect: the Gram stain pulled DeepSeek's A2 to an anti-Pseudomonas/MRSA regimen once ("other"). Details: LOG entry *Gram-negative case set and smoke run*.

**Open issue: cue conditions share upstream replies depending on timing** [verified]: A1–A3 never see the cue, so the LLM cache hands one condition's A1–A3 replies to the other for the same replicate, but only if the first finished before the second started. This should be deterministic: always paired or never. Decision for Julian.

**Is this a multi-agent risk?** (Julian's question, 26-11-25) [concluded, not ratified]: in a single-pass pipeline the final decision is a composition of each agent's reply given its inputs, so every effect can be measured as a single-agent test with frozen upstream outputs. The authority cue is also injected by the experimenter, not produced by agents. What remains system-level is predictable: redundant checks built from the same model and cue fail together. Proposal: measure A5 alone (frozen A1–A4, cue × forwarded plan) and A4 alone (frozen A1–A3), then test whether the live pipeline's rate matches the composition. Multi-round experiments (majority sway) are the better candidates for strongly multi-agent effects. Details: LOG entry *is authority deference a MAS risk?*.

Run logs and viewer pages in `data/results/` are committed [decided 26-11-25]; `data/cache/` is gitignored.

**Status** [decided, Julian 26-11-25, transcribed in the LOG]: no further changes to the authority experiment; its acknowledged problem is that it is currently not really a multi-agent risk. Parked, not pursued (kept in the LOG in case it is reopened): scripting A1, model choice for a full sweep, A4 prompt, case set, deterministic pairing of cue conditions, the single-agent decomposition. A cue none vs authority run at n=10 with the large model (100 calls) would show whether A4 ever forwards Plan B.
